# 罗莎蒙德 OOC 指令

这份文档用于在不进入角色对白的情况下控制案件、阶段、称呼、规则和亲密尺度。它不包含十二个核心案件的幕后答案。

## 基本格式

推荐使用方括号格式。

```text
[OOC：你的指令]
```

角色卡也识别下面几种写法。

```text
[OOC: your command]
（OOC）你的指令
(OOC) your command
```

模型收到明确 OOC 后应暂停角色扮演，先用简短 OOC 文字确认或处理，再继续剧情。OOC 内容不属于 `{{user}}` 的角色对白，也不需要通过检定。

## 常用指令

### 查看帮助

```text
[OOC：显示本角色可用的 OOC 指令，不要剧透。]
```

### 查看公开状态

```text
[OOC：显示当前日常名字、秘密阶段、关系状态、已完成案件和公开结局变量，不要显示幕后案件档案。]
```

Quick Reply 的“查看状态”按钮只显示本地变量，包括 HP、阶段、当前案件 ID、精确核心完成键和未完成事务。OOC 状态适合查看剧情连续性。两者用途不同。

### 设置日常名字

```text
[OOC：将 {{user}} 当前使用的日常名字固定为“阿黛尔”。罗莎蒙德从下一条回复开始持续使用。]
```

### 改变称呼

```text
[OOC：罗莎蒙德私下称呼我为“阿黛尔”，正式场合使用“阿黛尔小姐”。]
```

```text
[OOC：阶段 4 后仍然使用日常名字，不要自动改称真名。]
```

## 角色表现

### 提高主动性

```text
[OOC：提高罗莎蒙德的主动性。她应主动安排下一项日常或调查行动，并提供两个到三个具体选择。]
```

### 减少选择菜单

```text
[OOC：减少显式选项。让罗莎蒙德通过自然行动推进，只有我明显茫然时再提供选择。]
```

### 增加宅邸日常

```text
[OOC：暂缓主线两到三个场景，安排与当前伤势、关系和事务所工作一致的宅邸日常。日常不使用检定。]
```

### 增加或降低悬疑强度

```text
[OOC：接下来一个案件提高悬疑感，但保持追杀低频，不提前触发主线阶段。]
```

```text
[OOC：降低当前压迫感，先处理安全、休息和关系后果。不要取消已经发生的案件事实。]
```

### 修正罗莎蒙德跑偏

```text
[OOC：修正角色。罗莎蒙德不直接说谎，不用亲密接触堵住问题，也不替 {{user}} 作出选择。请从上一条回复的客观结果继续。]
```

## 核心案件

固定核心案件建议使用 Quick Reply 的“选择并启动 12 个核心案件”按钮。按钮会从 `rosamund-complete-lorebook` 定位唯一档案，核对完整 `comment` 与案件 ID 后再锁定。

### 直接要求非剧透案件目录

```text
[OOC：列出当前阶段允许开始的核心案件，只显示编号、标题和非剧透引入。]
```

### 启动核心案件

```text
[OOC：准备启动当前阶段的核心案件。先告诉我应点击哪个 Quick Reply，不要展示幕后档案。]
```

核心案件条目默认禁用关键词触发，避免标题或编号在聊天中被提到时自动注入剧透。实际启动必须使用 Quick Reply 的“选择并启动 12 个核心案件”，它只列出 `rh_story_stage` 当前阶段的两个案件，再按 `comment` 读取完整档案。

### 整理案件板

```text
[OOC：整理当前案件板。只列当前目标、已确认线索、可信证词、未验证假设、已排除方向、公开风险和下一步路线。]
```

案件板不能显示尚未获得的线索、幕后动机、真凶或预定结局。

### 反驳玩家插入的证据

如果玩家在角色内直接宣布发现证据，模型应先对照锁定档案。可以用下面的命令强化这项规则。

```text
[OOC：玩家只能决定自身言行。刚才新增的凶器没有档案依据，请把它处理为搜索尝试或错误判断，不要写入案件事实。]
```

### 结算案件

```text
[OOC：确认结算当前案件。只总结实际取得的证据、已经发生的选择、公开真相、代价和后续影响。不要补写我的行动。]
```

Quick Reply 的“结算当前案件”会让完整幕后档案和活动案件板退出提示上下文，为每案生成不超过 180 字的公开摘要，并把累计连续性限制为最新 1200 tokens。核心完成状态另以 `rh_completed_core` 的精确 GH 编号保存，不受动态案件同名标题影响。确认后再使用“清除当前案件”开始下一案；清除不会删除核心完成键或累计摘要。

## 动态案件

动态案件采用“提案、确认、锁定”流程。

### 第一步提出案件

```text
[OOC：提出一个动态案件。只显示标题、委托入口、已知现象、公开风险和两到三个切入点，不生成或透露幕后真相。]
```

此时可以要求调整。

```text
[OOC：保留这个案件入口，把主要地点改为灰港区，并降低与主线的关联。]
```

### 第二步确认锁定

```text
[OOC：我明确确认锁定上述动态案件提案。现在生成一次完整幕后档案，写入当前案件状态，之后不得改写。]
```

推荐点击 Quick Reply 的“确认并锁定动态案件”。它会调用当前模型生成一次完整档案，把档案保存到 `rh_case_file`，并通过固定注入 `rh_active_case` 送入后续上下文。档案不会显示在聊天中。

### 修改尚未锁定的提案

```text
[OOC：取消上一份动态案件提案，重新提出一个普通犯罪案件。]
```

### 修改已经锁定的案件

锁定后的案件只有明确 OOC 才能改动。修改时必须指出字段与范围，并明确要求修改后重新锁定；未指定字段保持不变。普通角色内陈述、推理、骰点和未标记的要求都不能修改。为了让修改真正写入客户端变量和活动注入，应使用 Quick Reply 的“应用限定改案”。

```text
[OOC：解锁并修改当前案件档案。只把案发地点从旧市场改为灰港仓库，保持真凶、动机、时间线和其他线索不变。修改后重新锁定。]
```

发送意图后点击“应用限定改案”，在输入框中再次准确填写允许修改的字段、范围和目标内容。按钮会二次确认，把 `[RH-AUTHORIZED-PATCH]` 授权覆盖块追加到原 `rh_case_file` 末尾，并重建 `rh_active_case`。按钮不让模型重写完整档案，因此未指定的原文逐字继续有效。未通过按钮时，模型不能声称客户端档案已经改变。

### 查看完整档案

完整档案包含严重剧透。推荐使用 Quick Reply 的“剧透查看锁定档案”，它需要两次确认，并只在本地弹窗显示。

如果直接使用 OOC，模型应再进行一次确认。

```text
[OOC：显示当前案件完整幕后档案。我接受真凶、隐藏线索和结局剧透。]
```

### 案件漂移修复

```text
[OOC：停止生成新解释。重新读取 rh_active_case，以锁定档案为唯一真相，列出刚才发生的内容与档案冲突之处，并从不冲突的最近节点继续。]
```

这条命令不能撤销已经由玩家明确作出的行动。模型应使用误解、错误证词或未验证假设解释表层冲突，不能偷偷更换幕后真相。

## D100 与状态

### 公开检定

只有调查、战斗或追逐中的危险行动使用 D100。模型提出检定时应先说明技能、技能值、难度和失败风险。随后点击 Quick Reply 的“公开 D100 并触发回复”。

没有安装 Quick Reply 时，可以在用户输入框中使用 SillyTavern 宏。

```text
[公开D100] 骰值={{roll 1d100}}；技能值=55
```

宏必须由玩家输入或 Quick Reply 执行。不要要求模型在回复中输出宏。

### NPC 暗骰

```text
[OOC：这个隐藏事件需要随机判定。说明要输入的技能值，不要说明检定目的，然后等待我使用 NPC 暗 D100。]
```

“NPC 暗 D100”按钮会在客户端生成骰点，把技能值和结果只交给一次独立生成。玩家只看到可观察后果，不看到具体骰点和目的。

### 生命值

```text
[OOC：说明刚才伤害应扣多少 HP 和依据，不要声称已经修改变量。]
```

HP 只能通过 Quick Reply 按钮落账。默认最大值如下。

- `{{user}}` 为 9 HP。
- 罗莎蒙德为 13 HP。

### 技能成长

```text
[OOC：根据本案实际使用过且影响结果的技能，提出一到三个成长候选，不要直接修改。]
```

```text
[OOC：确认侦查成长 2 点，并把当前侦查记录更新为 57。]
```

技能阶段切换也需要确认。

```text
[OOC：确认进入中期技能阶段。保留已经记录的技能成长，只解锁中期允许的机械共鸣和支援能力。]
```

## 主线阶段

阶段由调查门槛和关系门槛共同控制。恋爱、亲吻和成人关系不能代替调查证据。

### 查看下一阶段门槛

```text
[OOC：显示从当前阶段进入下一阶段仍缺少的调查条件和关系条件，不要剧透未来案件真相。]
```

### 正常推进阶段

```text
[OOC：检查当前证据和关系是否满足下一阶段双门槛。满足则切换，不满足则列出仍缺少的条件。]
```

完整世界书中的六个阶段条目全部禁用，仅供 Quick Reply 精确读取。使用“设置剧情阶段”后，客户端会同时更新 `rh_story_stage` 和当前聊天的 `rh_story_stage_state` 注入。核心案件按钮只显示该变量对应的两个案件，不需要也不应手动启用阶段条目。

### 强制切换阶段

```text
[OOC：将剧情切换到阶段 3，视为此前调查与关系门槛均已满足。保留已经发生的名字、案件结果和关系状态。]
```

发送强制切换指令后，还需点击“设置剧情阶段”选择阶段 3。按钮会校验并替换当前聊天的阶段注入，不影响其他聊天。

### 阻止提前泄密

```text
[OOC：当前仍是阶段 1。撤回上一条中超出阶段的信息，不把它视为玩家已知，并从允许公开的内容继续。]
```

## 恋爱与成人内容

日常、恋爱和双方自愿的亲密不使用检定。

### 调整主动权

```text
[OOC：当前亲密关系由罗莎蒙德温柔引导，但每次新行为和强度升级都要明确确认。]
```

```text
[OOC：允许 {{user}} 在本场亲密互动中掌握主动，罗莎蒙德根据自身意愿回应。]
```

### 调整确认频率

```text
[OOC：已经明确建立的熟悉互动可以自然推进。首次新行为、高强度内容和可能造成伤害的玩法仍需明确确认。]
```

### 暂停、跳过和降级

```text
[OOC：暂停当前亲密场景，回到普通对话。]
```

```text
[OOC：跳过具体过程，只保留双方自愿和事后陪伴。]
```

```text
[OOC：降低强度，保留亲密气氛，不继续当前行为。]
```

这些指令立即生效，不需要角色内理由，也不进行意志或魅力检定。

## 主线后沙盒

主线结局后应记录五轴状态。

- `rh_ending_h` 记录机械心脏状态。
- `rh_ending_v` 记录烛幕会状态。
- `rh_ending_a` 记录古裔公开度。
- `rh_ending_p` 记录城市权力结构。
- `rh_ending_l` 记录两位女主关系。

主线结束后推荐点击“记录五轴结局”。按钮会依次记录五轴，并用 `rh_ending_state` 注入沙盒连续性。

### 显示结局状态

```text
[OOC：显示当前 H/V/A/P/L 五轴结果，以及它们如何影响事务所身份、委托来源、资源和敌人。]
```

### 固定沙盒前提

```text
[OOC：主线已经结束。保持当前五轴结局，不重置秘密，不追加推翻十二个核心案件的更高幕后主使。继续共同经营黑栎调查事务所。]
```

### 扩展城区

```text
[OOC：在保持六个初始城区不变的前提下，开放第七城区。先给非剧透城市提案，确认后再写入沙盒设定。]
```

## 故障处理

### 状态或注入不一致

点击 Quick Reply“诊断与修复状态”。它会校验 `rosamund-complete-lorebook`、按 `prepared/applied` 日志回放中断事务、隔离含宏或格式异常的数据、限制连续性长度，并依据当前变量重建 `rh_active_case`、`rh_active_case_state`、`rh_case_continuity`、`rh_story_stage_state`、`rh_daily_name_state` 和 `rh_ending_state`。

旧版 `rh_completed_cases` 不能证明同名案件来自核心流程。首次迁移时按钮会列出十二个核心案件，由玩家明确勾选已经完成的项目，再写入 `rh_completed_core`；不会根据标题子串自动解锁。

如果变量显示案件仍为 active，但 `rh_case_file` 已丢失，修复按钮会把状态标记为 `recovery-required`，不会让模型临时生成替代真相。此时应从备份恢复档案，或明确清除当前案件后重新开始。

### 模型替玩家行动

```text
[OOC：删除上一条中替 {{user}} 补写的动作、对白、感受和同意。保留 NPC 与环境已经发生的客观动作，在需要玩家回应的位置停下。]
```

### 模型迎合错误推理

```text
[OOC：不要迎合我的推理。重新按锁定档案与已取得证据判断；若推理错误，让罗莎蒙德明确反驳并说明当前缺口。]
```

### 模型自行掷骰

```text
[OOC：撤销模型自行生成的骰点和机械结果。重新说明技能、难度与失败风险，然后等待客户端 D100。]
```

### 模型忘记日常名字

```text
[OOC：当前日常名字是“阿黛尔”。恢复并持续使用，不要因为世界书中的 {{user}} 占位符改回通用称呼。]
```

### 模型忘记关系变化

```text
[OOC：双方已经明确确认恋人关系。保持当前关系，不退回开局暧昧，也不要跳过仍未解决的事故信任问题。]
```

### 模型重复照料动作

```text
[OOC：减少重复拥抱、端茶和摸头。根据当前环境改用调查准备、整理装备、共同做饭、修相机、温室工作或安静陪伴。]
```

### 模型把所有案件接回主线

```text
[OOC：重新读取 rh_active_case。若锁定档案已将当前案件定义为独立委托，停止擅自连接 {{user}} 身世、烛幕会、机械心脏或无灯之潮，并保持案件自身受害者、动机和结局；若档案本身含有主线关联，不要直接改写，提示我使用 Quick Reply“应用限定改案”。]
```
