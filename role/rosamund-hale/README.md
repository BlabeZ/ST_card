# 罗莎蒙德·黑尔角色包

这是一个面向长期游玩的 SillyTavern 模块化角色包。主线围绕失忆、固定案件真相、烛幕会和机械心脏展开。主线结束后，两位女主继续经营黑栎调查事务所，进入没有固定终点的城市沙盒。

## 安装文件

| 文件 | 用途 | 是否必需 |
| --- | --- | --- |
| `rosamund-hale.character.json` | Character Card V2 角色卡 | 必需 |
| `rosamund-complete-lorebook.json` | 62 条城市、组织、配角、规则、核心案件与阶段内容 | 完整体验必需 |
| `rosamund-quick-replies.json` | 客户端骰子、HP、案件状态、核心案件启动与限定改案按钮 | 游玩固定主线时必需 |
| `rosamund-ooc-commands.md` | OOC 控制、纠错和调试指令 | 推荐阅读 |

顶层只保留发行文件和玩家文档。创作者剧透设定、拆分世界书、构建测试、哈希清单及历史评审报告统一收纳在 `archive/`，详见 `archive/README.md`。完整安装不要导入 `archive/development/sources/` 中的拆分世界书，否则会产生重复条目。

## 最简导入

只想先体验角色时，导入 `rosamund-hale.character.json` 即可。角色卡已经包含罗莎蒙德、固定玩家外貌、初始场景和少量基础城市设定。

这种模式没有完整城区、常驻配角、固定案件档案和客户端 D100 状态管理。

## 完整导入

1. 在角色管理界面导入 `rosamund-hale.character.json`。
2. 若出现 `Import Card Lore` 或同类选项，选择跳过。卡内三条基础 Lore 只用于单卡模式，完整世界书和角色卡正文已经覆盖这些内容。
3. 在世界书界面只导入 `rosamund-complete-lorebook.json`。
4. 把完整世界书绑定为当前角色或聊天可用的 Character Lore、Additional Character Lore 或 Chat Lore。
5. 在 Quick Replies 扩展中导入 `rosamund-quick-replies.json`，并为当前聊天启用预设 `Rosamund-D100`。
6. 点击“初始化状态”。按钮会校验完整世界书、迁移旧状态、注入阶段 0，并重置 HP 与技能阶段。

不同 SillyTavern 版本对世界书绑定入口命名可能不同。常见名称包括 Character Lore、Additional Character Lore、Chat Lore、World Info 和 Lorebook。

## 不要重命名完整世界书

Quick Reply 使用下面的固定名称读取案件档案。

```text
rosamund-complete-lorebook
```

导入 `rosamund-complete-lorebook.json` 后，请保留这个世界书名称。核心案件、阶段切换、初始化和状态修复都会按名称读取条目，并在模糊检索后核对完整 `comment`。读取失败或身份不符时不会覆盖现有状态。

## Quick Reply 启用

Quick Replies 默认可能处于关闭状态。请先在扩展面板启用，再导入预设。

可以通过界面把 `Rosamund-D100` 绑定到当前聊天，也可以使用当前 STscript 命令。

```text
/qr-chat-set-on Rosamund-D100
```

主要按钮如下。

| 按钮 | 功能 |
| --- | --- |
| 初始化状态 | 校验完整世界书、迁移修复状态，再设置双方 HP 和前期技能阶段 |
| 公开 D100 并触发回复 | 客户端生成 `1d100`，计算成功等级并发送给模型 |
| NPC 暗 D100 | 客户端生成隐藏骰点，只显示可观察后果 |
| 查看状态 | 本地弹窗显示 HP、阶段、案件 ID、核心完成键和未完成事务 |
| 设置剧情阶段 | 精确读取目标阶段，并用 `rh_story_stage_state` 只替换当前聊天的阶段约束 |
| 记录日常名字 | 保存 `rh_daily_name` 并通知模型持续使用 |
| HP 加减 | 修改聊天局部变量中的当前 HP |
| 整理案件板 | 生成玩家已知调查笔记，并持久保存有界 `rh_active_case_state` |
| 提议动态案件 | 只生成非剧透提案，不建立幕后真相 |
| 确认并锁定动态案件 | 二次确认后生成一次幕后档案并持久注入 |
| 选择并启动 12 个核心案件 | 读取正式固定档案并启动 |
| 应用限定改案 | 把授权覆盖块追加到原档案末尾；只覆盖明确字段，其他原文逐字保留 |
| 结算当前案件 | 生成可见结案，精确记录核心完成 ID，并把累计连续性限制为最新 1200 tokens |
| 剧透查看锁定档案 | 两次确认后在本地弹窗显示完整档案 |
| 清除当前案件 | 清除活动案件变量和 `rh_active_case`，保留累计结案连续性 |
| 记录五轴结局 | 主线后依次保存 `rh_ending_h/v/a/p/l` 并注入沙盒状态 |
| 诊断与修复状态 | 回放中断事务、隔离异常数据、确认迁移旧核心进度，并重建聊天局部注入 |

所有状态变量使用 `rh_` 前缀，并保存于当前聊天。切换到其他聊天不会共享。

## D100 流程

跑团规则只用于调查、战斗或追逐中有真实风险的行动。日常生活、普通交谈、恋爱、亲密、选择名字、无压力行为及不属于这三类的场景不检定；外部危险介入时先明确切换规则。

标准流程如下。

1. 罗莎蒙德说明技能、当前技能值、要求的成功等级和失败风险。
2. 模型停止结算，等待玩家点击“公开 D100 并触发回复”。
3. Quick Reply 在客户端执行 `{{roll 1d100}}`。
4. 模型读取已经计算好的成功等级，并按照锁定案件档案叙述结果。

模型不得自行编造骰点，也不得在回复中输出宏冒充工具调用。

没有 Quick Reply 时，可以在用户输入框手动发送。

```text
[公开D100] 骰值={{roll 1d100}}；技能值=55
```

## 成功等级

| 条件 | 结果 |
| --- | --- |
| `01` | 大成功 |
| 不高于技能值五分之一 | 极难成功 |
| 不高于技能值二分之一 | 困难成功 |
| 不高于技能值 | 常规成功 |
| 高于技能值 | 失败 |
| 技能低于 50 时的 `96-100`，或技能至少 50 时的 `100` | 大失败 |

骰点只能改变时间、危险、伤亡、证据完整度、人物去向、资源和关系后果。它不能改变凶手、动机、方法、时间线和线索位置。

## 核心案件流程

十二个核心案件按照秘密阶段排列，每阶段两个。档案条目默认禁用关键词触发，避免聊天提到案件编号或标题时自动注入剧透；通过 `/findentry` 读取禁用条目不受影响。核心案件必须通过 Quick Reply 启动。

1. 点击“选择并启动 12 个核心案件”。
2. 按钮根据 `rh_story_stage` 只显示当前阶段允许的两个案件。
3. 再次确认启动。
4. Quick Reply 从 `rosamund-complete-lorebook` 模糊定位条目，再核对完整 `comment` 和案件 ID，确认无误后保存到 `rh_case_file`。
5. 档案通过固定 ID `rh_active_case` 注入后续上下文。
6. 模型只从非剧透入口开始，不展示完整档案。

固定案件档案包含真凶或责任主体、动机、完整时间线、NPC 知情范围、真线索、预写误导、证据位置、错误推理反驳、检定影响和多维结局。

## 动态案件流程

动态案件需要明确 OOC 确认。

1. 点击“提议动态案件”。
2. 查看不含真凶与解法的提案。
3. 可以通过 OOC 要求修改地点、题材和风险。
4. 满意后点击“确认并锁定动态案件”。
5. 再次确认。
6. Quick Reply 调用当前模型生成一次完整幕后档案，保存并注入。

锁定后不会自动重生成。只有明确标记的 OOC 指令可以修改，而且必须指定字段与范围并在修改后重新锁定。需要实际修改时使用“应用限定改案”。按钮不会让模型重写完整档案，而是把 `[RH-AUTHORIZED-PATCH]` 覆盖块追加到原档案末尾；只有其中明确列出的字段发生变化，其他原文逐字继续有效。

核心案件启动、动态案件锁定、结案、五轴提交和限定改案使用三段式事务：先保存 `prepared` 日志，再保存 `applied` 状态，最后清除日志并再次保存。若中途关闭页面或生成失败，“诊断与修复状态”会按事务类型幂等回放，不会重复增加结案数或连续性摘要。

## 玩家叙事权限

玩家只控制 `{{user}}` 的言行、调查方式和推理。NPC、环境、证据、调查结果与案件世界事实由模型按照锁定档案控制。

下面的玩家输入不能直接创造证据。

```text
我打开抽屉，发现了带血的凶器。
```

如果档案中没有该证据，模型应把它理解为搜索尝试，并明确说明抽屉中没有凶器。玩家可以提出错误理论，罗莎蒙德会依据现有证据反驳。

## HP 与存续

- `{{user}}` 最大 HP 为 9。
- 罗莎蒙德最大 HP 为 13。
- 八名常驻配角不使用常驻数值面板，但遵循同样的非永久死亡规则。
- 核心人物可以重伤、昏迷、被捕、失踪、留下后遗症、失去职位或暂时退场。
- 案件临时人物和其他居民可以死亡。
- 不使用复活或神秘免死解释核心人物存续。

HP 只能通过 Quick Reply 按钮修改。模型可以说明应扣除或恢复多少，不能声称已经改动变量。

## 阶段切换

完整世界书包含阶段 0 至 5 六个检索专用条目，它们全部保持禁用，不通过关键词自动触发。初始化和“设置剧情阶段”会精确读取一个阶段，并通过固定 ID `rh_story_stage_state` 只注入当前聊天。

每次推进都需要调查门槛和关系门槛同时满足。恋爱、亲吻、成人关系和依赖不能替代证据。满足门槛后点击“设置剧情阶段”，确认目标阶段。按钮会先校验条目，再同时更新 `rh_story_stage` 与当前聊天注入；不会修改其他聊天或全局世界书条目。

如果阶段变量、案件注入或连续性注入在中断后不一致，点击“诊断与修复状态”。修复会根据已保存变量重建注入；活动状态存在但权威档案丢失时会标记为 `recovery-required`，不会生成替代真相。

强制测试后期内容时可以使用 OOC。

```text
[OOC：将剧情切换到阶段 3，视为此前调查与关系门槛均已满足。保留现有名字、案件结果与关系。]
```

## 主线后沙盒

主线结束后记录五轴状态。

| 变量 | 内容 |
| --- | --- |
| `rh_ending_h` | 机械心脏状态 |
| `rh_ending_v` | 烛幕会状态 |
| `rh_ending_a` | 古裔公开度 |
| `rh_ending_p` | 城市权力结构 |
| `rh_ending_l` | 两位女主关系 |

主线结束后点击“记录五轴结局”，客户端会保存五轴并注入 `rh_ending_state`。五轴决定事务所是否合法、有哪些委托人、能够使用哪些资源，以及哪些组织继续敌对。沙盒不会重置秘密或关系，也不会追加推翻十二案的更高幕后主使。

## 成人恋爱

双方均为成年人。成人内容可以完整描写，卡内不预设题材黑名单。

- 熟悉且已经明确建立的互动可以自然推进。
- 首次新行为、高强度内容和可能造成伤害的玩法需要明确确认。
- 一次同意不会自动延伸到其他行为或未来场景。
- OOC 暂停、跳过和降低强度立即生效。
- 日常安慰和拥抱不会自动升级为成人内容。
- 失忆、依赖、救命关系和信息差不能成为施压工具。

详细命令见 `rosamund-ooc-commands.md`。

## 已知限制

- Quick Reply 与 STscript 格式依据 SillyTavern `1.18.0` 当前官方源码和文档制作，较旧版本可能缺少部分命令或 version 2 导入格式。
- 动态案件档案由当前连接的模型生成。锁定机制能阻止后续随意改写，不能保证所有模型第一次生成的档案质量完全一致。
- NPC 暗骰由客户端生成数值，但最终可观察后果仍由当前模型根据档案解释。
- 聊天局部变量和注入不会跨聊天自动共享。开始新聊天时需要重新初始化，并补入需要继承的名字、阶段、案件摘要和五轴状态。
- 尚未在本工作区内运行真实 SillyTavern UI，因此导入和按钮执行需要在你的酒馆版本中进行一次实际检查。

## 开发与校验

拆分世界书位于 `archive/development/sources/`，是完整世界书的唯一开发源。修改任一源文件后，在本目录运行：

```bash
python3 archive/development/build_complete_lorebook.py
python3 archive/development/test_rosamund_package.py
```

发布前可以用只读检查确认整合书与清单没有过期：

```bash
python3 archive/development/build_complete_lorebook.py --check
```

构建器固定按城市、组织、配角、规则、核心案件、阶段的顺序合并 62 条内容，重新编号 `uid`、对象键和 `displayIndex`。它保留源条目的其他字段，仅强制核心案件与阶段条目保持禁用，并强制核心案件 `sticky` 为 `null`。
