# 文明大域·禁物信使

## 文件

- `forbidden-courier.character.json` 是可直接导入SillyTavern的Character Card V2角色卡。
- `forbidden-courier-worldbook.json` 是角色专用世界书，包含世界规则、七大霸权、三条固定阴谋和八份固定委托档案。
- `forbidden-courier-quick-replies.json` 提供客户端D100、固定委托锁定、动态委托锁定、委托板、结案、清案和状态修复功能。
- `world-bible.md` 是完整可读设定总纲，不需要导入。

## 导入顺序

1. 导入 `forbidden-courier.character.json`。
2. 导入 `forbidden-courier-worldbook.json`，并把它设为本角色的Character Lore或当前聊天的Chat Lore。
3. 导入 `forbidden-courier-quick-replies.json`。
4. 不要重命名世界书。Quick Reply按 `forbidden-courier-worldbook` 这个名称读取固定档案。
5. 创建新聊天并使用默认开场。
6. 决定接受哪份固定委托后，点击“选择并锁定固定委托”，选择同名档案并确认。锁定完成后再进入任务。

角色卡没有附带头像。导入后可以自行上传图片，不影响设定。

## D100流程

模型只在结果真正不确定、失败会产生有意义后果时提示下面这句话，并停止剧情。

`需要进行随机判定。`

此时点击“公开D100并触发回复”。这次点击本身就是确认。按钮按消息索引读取最后一条可见消息，要求它属于模型并以该句作为独立末行；已消费请求同时按完整消息文本去重，因此删除前文导致索引重排也不能重复掷骰。随后由SillyTavern客户端执行 `{{roll 1d100}}`，并公开发送实际点数。模型不得自行掷骰。

| 点数 | 结果倾向 |
| --- | --- |
| 1至20 | 明显不利 |
| 21至40 | 轻微不利 |
| 41至60 | 中性或成败参半 |
| 61至80 | 有利 |
| 81至100 | 明显有利 |

骰点只影响结果倾向、代价、时间、位置、暴露和证据状态，不改变固定真相、责任人、人物核心动机或既定历史。

骰点宏只放在Quick Reply中。若把它写进角色卡或常驻世界书，SillyTavern会在处理提示时解析它，容易出现每轮误掷。

## 固定委托

世界书内置八份完整幕后档案。

- FC01《灰港仍有春天》
- FC02《把太阳还给禾瓣城》
- FC03《给夜班送一轮日出》
- FC04《没有第九页的和约》
- FC05《请为无名者签收》
- FC06《借来的十二双手》
- FC07《第四十七秒》
- FC08《两颗彗星不该相逢》

默认开场公开FC01、FC02、FC03和FC07。其余固定委托可以在后续停靠时通过中间人、客户或Quick Reply启动。

Quick Reply会把选中的幕后档案读入聊天变量，并用固定id `fc_active_case` 注入系统上下文。已有当前委托时不会覆盖。

八份固定委托档案在世界书中保持禁用，只由Quick Reply按选择读取，避免标题触发剧透。三条完整阴谋档案是常驻作者层，始终为模型固定幕后事实，但叙事规则禁止模型在玩家取得证据以前直接泄露。不要手动改变这些条目的启用状态。

## 动态委托

动态委托严格分为两个步骤。

1. 点击“提议动态委托”，只生成玩家可见的非剧透提案。
2. 确认愿意游玩后，点击“确认并锁定动态委托”。按钮会在后台只生成一次完整档案并注入当前聊天。

锁定后不能因玩家猜测、骰点或剧情方便更换真相。动态档案的质量依赖当前模型，建议使用擅长长文本一致性和指令遵循的模型。

动态提案、幕后档案、委托板和结案文本都会经过非空检查，并拒绝包含宏定界符的生成结果，防止模型文本重新进入客户端宏引擎。

## 长期阴谋

世界书预置三条彼此独立的长期线。

- 静默修约涉及1204特科内部校订组和停战条约因果改写。
- 借身工厂涉及跨域企业赫典人格工业共同体批量复制并剥夺人格权的生产意识。
- 盲航账簿涉及航道共和国保险集团制造事故以完成终途罗盘。

三条线没有共同幕后黑手。多数委托与它们无关。用户拒绝追查时，相关势力仍按档案中的时间表行动。

## 世界书建议

- 建议扫描深度为4至6。
- 中文关键词不要启用整词匹配。
- 不需要向量匹配，固定关键词更可预测。
- 世界书条目保持非递归即可。固定委托通过Quick Reply直接注入，不依赖关键词递归。
- 常驻条目包含运行规则与三条完整阴谋档案；地区和国家条目按关键词触发。若模型上下文较小，优先减少聊天回溯，不要禁用阴谋档案，否则长期真相会失去权威来源。

## 状态恢复

提案、动态锁定和结案等待模型生成时会分别占用proposing、locking和closing状态，并为每次操作生成独立令牌。提交前必须同时匹配阶段与令牌，旧生成即使遇到同阶段的新操作也不能覆盖。点击“清除当前委托”可以明确取消仍在生成的操作，迟到结果会因令牌失效而被丢弃。

如果客户端中断后出现委托变量存在但模型像是没有读取档案，点击“诊断与修复委托状态”。按钮会依据 `fc_case_file` 重建 `fc_active_case` 并强制保存；已经结案的委托会保留closed标记，不会被重新激活。未完成的proposing会回滚，locking会按权威档案是否已提交决定回滚或完成，closing会安全恢复active。若档案本身已经丢失，按钮只会标记 `recovery-required`，不会让模型临时编造替代真相。

SillyTavern官方文档说明角色描述、性格和场景属于常驻上下文，世界书按关键词动态插入内容，宏会在提示、角色卡、世界书和Quick Reply等支持字段中解析。
