# 妮薇长期 RP 配置说明

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `nive.character.json` | 妮薇的人格、行为、文风、能力和关系起点 |
| `master-persona.md` | `{{user}}` 的稳定身份与妮薇专用 Persona 描述 |
| `nive-shared-lorebook.json` | 两人跨聊天共享的家园、生活、装备、收入和关系基础 |
| `nive-story-stages-lorebook.json` | 当前聊天独有的长期剧情阶段与隐藏血裔线 |
| `nive-dnd-lorebook.json` | 按需加载的轻量 D&D 外部舞台 |
| `nive.md` | 供创作者阅读和修改的完整设定书 |

本配置不包含 Author's Note 状态模板。

## 一　导入角色卡

在 SillyTavern 的角色管理页面导入 `nive.character.json`。

角色卡负责妮薇自身。她的性格、母性、依恋、道德观、能力、血统经历与当前认知应继续保留在角色卡中。

## 二　创建 Persona

1. 打开 Persona Management。
2. 创建新的 Persona，并设置你想使用的显示名和头像。
3. 将 `master-persona.md` 中的 Persona Description 粘贴进去。
4. 保持 Position 为 `In Story String / Prompt Manager`。
5. 将 Persona 锁定到妮薇角色或当前聊天。

当前 Persona 保留姓名、种族、性别、职业和外貌的自由。准备长期使用同一个主角时，再把这些字段逐步补齐。

## 三　导入双人 Character Lore

导入 `nive-shared-lorebook.json`，随后把它设置为妮薇的主要 Character Lore。

该世界书共有八条内容。

| UID | 条目 | 激活方式 |
| --- | --- | --- |
| 0 | 双主角叙事核心 | 常驻 |
| 1 | 两人的家 | 关键词 |
| 2 | 共同生活与分工 | 关键词 |
| 3 | 草药田与药剂研究 | 关键词 |
| 4 | 共同装备与锻造 | 关键词 |
| 5 | 共同收入与集市 | 关键词 |
| 6 | 拍卖场救援 | 关键词 |
| 7 | 关系与长期愿望 | 关键词 |

主要 Character Lore 会在角色卡从 SillyTavern 再次导出时一同嵌入。其他附加世界书通常需要单独备份。

## 四　绑定聊天剧情世界书

导入 `nive-story-stages-lorebook.json`，把它绑定为当前聊天的 Chat Lore。

初始状态只有阶段 0 启用，阶段 1 至阶段 6 全部禁用。任何时候只保留一个阶段启用。

推进方式如下。

1. 当前剧情获得该阶段要求的可靠证据。
2. 禁用旧阶段。
3. 检查并补全新阶段条目中的实际人物、地点和已发生事件。
4. 启用新阶段。
5. 通过 Prompt Itemization 确认只有新阶段进入上下文。

未来阶段条目保持禁用时，模型不会读取其中的隐藏真相。不要同时启用多个阶段，也不要依靠血脉感应、梦境或无依据的直觉跳过调查。

随着聊天推进，可以在同一 Chat Lore 中新增共同经历、装备变化、已认识 NPC 和已完成委托。每条内容只记录已经发生并需要长期保留的事实。

## 五　导入轻量 D&D 世界书

导入 `nive-dnd-lorebook.json`。建议将它作为妮薇的附加 Character Lore；如果多个角色共用同一套世界，也可以作为全局 World Info 启用。

该世界书只包含四条内容。

| UID | 条目 | 激活方式 |
| --- | --- | --- |
| 0 | 本故事的 D&D 叙事规则 | 常驻 |
| 1 | 本故事中的深水城 | 明确地名触发 |
| 2 | 剑湾与北地旅行 | 地区与旅行词触发 |
| 3 | 冒险与魔法生态 | 相关场景触发 |

后续只添加当前剧情实际使用的组织、地区与 NPC。不要预先导入被遗忘国度百科。

## 六　World Info 建议设置

- 中文条目保持 `Match whole words` 关闭，本次生成的每条记录已经显式设置为 `false`。
- 当前三份世界书都禁止递归激活，避免一个关键词拉入整套设定。
- 激活概率保持 100。
- 世界书预算以同时激活的内容长度为准，不以总条目数量为准。
- 通过回复消息的 Prompt Itemization 检查每轮实际进入上下文的条目。
- 如果宽泛关键词造成误触发，优先缩小关键词，不直接删除条目内容。

## 七　关系状态

所有文件采用同一关系起点。

```text
妮薇与{{user}}彼此深爱，拥有超越普通主仆的深厚依恋。
故事开始时，两人尚未正式确认恋人、伴侣或配偶身份。
正式身份可以在 RP 中自然推进。
```

初始状态只约束新聊天。关系一旦在当前 RP 中得到正式确认，应以最新聊天事实为准，不再退回未确认状态。
